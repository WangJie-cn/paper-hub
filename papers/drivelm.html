🛣️ DriveLM: Driving with Language

arxiv: 2312.14150 | 作者: OpenDriveLab (上海AI Lab) | 年份: 2024

一句话总结

构建 Graph VQA 数据集和基准，用结构化的问答形式表示驾驶场景的 感知-预测-规划 全流程。

核心贡献

  1. DriveLM 数据集 — 377K QA 对，覆盖感知/预测/规划
  2. Graph VQA — 用图结构组织 QA，体现逻辑依赖
  3. DriveLM-Agent — 基于 VLM 的端到端驾驶 agent
  4. 基准测试 — 评估 VLM 的驾驶理解能力

Graph VQA 设计

传统 VQA:
Q: "图中有什么车辆？"
A: "有一辆红色轿车"
→ 独立问答，无逻辑关联

Graph VQA:
┌─────────────────────────────────────────────┐
│  感知层                                      │
│  Q1: "检测到哪些物体？" → A1: [car_1, ped_2] │
└──────────────────┬──────────────────────────┘
                   │ 依赖
                   ▼
┌─────────────────────────────────────────────┐
│  预测层                                      │
│  Q2: "car_1 会怎么移动？" → A2: "向左变道"   │
└──────────────────┬──────────────────────────┘
                   │ 依赖
                   ▼
┌─────────────────────────────────────────────┐
│  规划层                                      │
│  Q3: "自车应该怎么做？" → A3: "减速让行"    │
└─────────────────────────────────────────────┘

三层结构

层级 任务 示例问题
Perception 目标检测、属性识别 检测到哪些车辆？它们在哪个车道？
Prediction 行为预测、轨迹预测 这辆车接下来会怎么做？
Planning 决策、轨迹规划 自车应该加速还是减速？

关键洞察

1. 为什么需要 Graph？

  • 驾驶是 链式推理：感知 → 预测 → 规划
  • 后续问题 依赖 前面的答案
  • Graph 结构让 VLM 学会这种依赖关系

2. 语言的优势

  • 可解释性 — 为什么做这个决策？
  • 泛化性 — 语言描述更抽象
  • 交互性 — 可以追问

个人思考

DriveLM 的核心思想是把驾驶问题"语言化"。传统方法输出数值（轨迹点），DriveLM 输出语言（"减速让行"）。这不仅提供可解释性，还可能让模型学到更抽象的驾驶知识。Graph 结构的设计也很聪明——它强制模型学习因果关系，而不只是输入-输出映射。
