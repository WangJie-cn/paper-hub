✍️ SigLIP: Sigmoid Loss for Language Image Pre-Training

arxiv: 2303.15343 | 作者: Xiaohua Zhai 等 (Google) | 年份: 2023

一句话总结

把 CLIP 的 Softmax 对比损失换成 Sigmoid 二分类损失，训练更简单、扩展性更好，效果还更强。

核心贡献

  1. Sigmoid Loss — 每对图文独立判断是否匹配
  2. 去掉全局归一化 — 不需要 all-gather，分布式更简单
  3. 更好的扩展性 — 支持更大 batch size
  4. 更强性能 — 同规模下超越 CLIP

CLIP vs SigLIP 损失函数

CLIP: Softmax (InfoNCE)

# 需要全局归一化 (所有负样本的指数和)
L_clip = -log( exp(sim(I_i, T_i)/τ) / Σⱼ exp(sim(I_i, T_j)/τ) )

# 问题：
# 1. 需要 all-gather 所有 GPU 的样本
# 2. 内存 O(batch²) 用于相似度矩阵
# 3. 负样本数量 = batch_size - 1

SigLIP: Sigmoid (Binary)

# 每对独立做二分类
z_ij = sim(I_i, T_j) * γ + b  # γ, b 是可学习的
y_ij = 1 if i==j else -1     # 正样本+1，负样本-1

L_siglip = -log(σ(y_ij * z_ij))  # 标准二分类

# 优势：
# 1. 不需要全局归一化
# 2. 可以做 chunked 计算，省内存
# 3. 正负样本比例可调

直观理解

CLIP 思路:
"在 batch 中，(图i, 文i) 是唯一匹配的"
→ 相对排名问题

SigLIP 思路:
"(图i, 文j) 这一对，匹配还是不匹配？"
→ 独立二分类问题

结果：SigLIP 更简单，效果更好！

实现细节

Chunked Sigmoid Loss

# 不需要一次算完整个 B×B 矩阵
for chunk_i in chunks(images):
    for chunk_t in chunks(texts):
        # 只算当前 chunk 的损失
        loss += sigmoid_loss(chunk_i, chunk_t)

# 内存: O(chunk_size²) instead of O(batch²)

Bias 初始化

# 重要！bias 初始化为 -10
# 让初始预测偏向"不匹配"（因为大部分对确实不匹配）
b = -10

代码示例

import torch
import torch.nn.functional as F

def siglip_loss(image_emb, text_emb, temperature=1.0, bias=-10.0):
    """
    SigLIP Sigmoid Loss
    """
    # 计算相似度矩阵
    logits = image_emb @ text_emb.T * temperature + bias
    
    # 构建标签：对角线为 1，其他为 -1
    n = logits.shape[0]
    labels = 2 * torch.eye(n, device=logits.device) - 1
    
    # Sigmoid 二分类损失
    loss = -F.logsigmoid(labels * logits).mean()
    
    return loss

# 使用
image_features = model.encode_image(images)  # (B, D)
text_features = model.encode_text(texts)     # (B, D)

# 归一化
image_features = F.normalize(image_features, dim=-1)
text_features = F.normalize(text_features, dim=-1)

loss = siglip_loss(image_features, text_features)

为什么 Sigmoid 更好？

  1. 独立性 — 每对独立评估，不受其他样本影响
  2. 稳定梯度 — 避免 softmax 的数值问题
  3. 灵活负样本 — 可以用更多负样本
  4. 简单分布式 — 不需要跨 GPU 同步

应用

SigLIP 被广泛用于新一代 VLM：

  • PaLI-X — Google 的多模态大模型
  • Gemini — Google 的 VLM
  • LLaVA-NeXT — 用 SigLIP 做视觉编码器

个人思考

SigLIP 告诉我们：简单往往更好。Softmax 的"竞争"机制看起来合理，但 Sigmoid 的"独立判断"更直接。而且从工程角度，去掉 all-gather 让分布式训练简单太多了。
