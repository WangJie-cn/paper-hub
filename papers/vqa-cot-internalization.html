🧠 VQA 训练与 CoT 能力内化机制

🔬 待深入研究

❓ 核心问题

为什么用 QA 训练的模型，推理时可以不需要 Question？能力是如何"内化"的？

1. 现象描述

训练时:
Image
+
"What objects?"
→
Answer
推理时:
Image
→
Trajectory
(不需要 Question!)

2. 直观类比

阶段 学开车 VLM 训练
学习时 教练问"前面有什么？该怎么办？" QA prompt 引导推理
熟练后 直接反应，不需要自问自答 直接 image → action

QA 不是目的，而是训练工具——强迫模型学会正确的注意力分配和推理路径。

3. 数学原理 (待研究)

3.1 条件概率视角

P(answer | image, question)

当 question 是固定模板时：

P(action | image, qfixed) ≈ P(action | image)

Question 退化为"格式提示"，实际学的是 image → answer 的直接映射。

3.2 信息论视角

I(Answer; Question | Image) = 0 ?

如果给定 Image，Question 不提供额外信息，那么模型学的是 I(Answer; Image)。

3.3 特征空间"雕刻"

训练前: 通用视觉-语言特征空间
↓ QA 微调 ↓
训练后: 任务特化特征空间
行人特征 → 激活"减速"方向
红灯特征 → 激活"停车"方向

4. 实现方案

方案 A: 多任务联合训练

loss = λ1·L_perception + λ2·L_prediction + λ3·L_planning + λ4·L_trajectory

共享 encoder + LLM，多个输出头。推理时只用 trajectory head。

方案 B: 两阶段训练

阶段1: 完整 CoT 训练 → 阶段2: 冻结参数，只微调最后几层输出轨迹

方案 C: 知识蒸馏

Teacher (大模型 + CoT) → Student (小模型，直接输出)

loss = MSE(student_traj, teacher_traj) + MSE(student_hidden, teacher_hidden)

5. 车端 HMI 同时输出 CoT

如果需要在车端显示推理解释：

推荐: 结构化 CoT 输出

return { 'scene': cls(h), # 分类: 城市/高速 'action': cls(h), # 分类: 17类 meta-action 'risk': reg(h), # 回归: 风险分数 'trajectory': reg(h) # 回归: 轨迹点 }

✓ 一次 forward (~50ms)，无需自回归
